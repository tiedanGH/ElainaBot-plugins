# AI 画图

任何人都能用的文生图插件。群聊、私聊、频道里发 `画图 <描述>` 就出图。

接口、密钥、模型目录全部由 `modules/ai_llm` 中央模块管理，**本插件不保存任何凭据**，
只在自己的配置里记 `provider_id` / `model` 这种选择。

---

## 依赖

| 模块 | 必需 | 说明 |
|---|---|---|
| `modules/ai_llm` | ✅ | 至少配好一个支持生图的接口与模型 |
| `modules/image_hosting` | 推荐 | 出图后上传图床拿直链，才能发 Markdown 图片消息 |

缺 AI LLM 时面板整体灰化并提示去插件市场下载；缺图床时自动退回富媒体图片消息。

---

## 指令

| 指令 | 权限 | 说明 |
|---|---|---|
| `画图 <描述>` | 所有人 | 生成并发送一张图 |
| `绘图` / `AI画图` | 所有人 | 别名，用法相同 |
| `画图` | 所有人 | 查看用法、当前尺寸、可用线路数 |

支持可选 `/` 前缀，描述可跨行；最大字数在面板「限流」页可调（默认 1000）。

## 为什么要走图床

QQ 的富媒体消息（`msg_type=7`）**不解析 `<@openid>`** —— 直接 `reply_image` 的话，
开头的 @ 只会以原文形式显示。所以默认改发 Markdown（`msg_type=2`）：

```
<@用户openid> 可选说明文字
![AI画图 #1024px #1024px](https://图床直链)
```

图片先经 Image Hosting 上传；接口只返回 URL 时会先下载再上传，保证域名是自己配的图床。
`#Wpx #Hpx` 由不依赖 Pillow 的头部解析器读出（PNG / JPEG / GIF / WebP）。

> ⚠️ **Markdown 图片的域名必须已在 QQ 开放平台报备**，否则图片不显示。
> 开着「校验图片资源」时未报备会判失败并退回富媒体，不会静默发出一条空图。

三级降级：图床上传失败 → 平台拒绝 Markdown → 退回富媒体图片消息。
私聊不带 @（没有提及语义），群聊与频道按「群内 @发起人」开关决定。

### 发送成功的判据

`reply()` / `reply_image()` 在平台失败时**也会返回响应体**（错误 JSON），
所以 `bool(response)` 判不出成败，必须看 `response['id']` 有没有消息 ID。
判错的话 Markdown 失败永远不会触发降级。

### 生成成功却没送达 → 换线路重来

常见于接口只返回一个 URL、而那个 URL 本地下不下来、平台也拉不动（链接过期、
指向内网、被防盗链挡住）。这时图是「生成成功」的，用户却什么都没收到。

所以投递失败会被判定为**这条线路的问题**，自动排除它、用下一条线路重新生成，
次数由面板「投递失败换线路重试次数」控制（默认 2，最多 5，同时不超过可用线路数）。

只有一种失败不重试：**图床上传成功、Markdown 却被平台拒收**。那是图床域名没报备，
换线路拿到的还是同一个域名，重试纯属白烧额度。

成功送达时历史里会记下先前失败的线路；全部试完仍失败则逐条记录原因。
用户始终只会收到一张图或一条失败提示，不会重复。

## Gemini 等多模态模型：走对话端点

`gemini-3.1-flash-image`（Nano Banana 2）这类模型**不是纯生图模型，而是多模态 LLM**，
所以多数中转不把它挂在 `/v1/images/generations` 上。直接当生图模型调会收到：

```
HTTP 400: Model gemini-3.1-flash-image is not supported on /v1/images/generations
or /v1/images/edits. Use gpt-image-2, grok-imagine-image, ...
```

每条线路因此多了一个**出图方式**：

| 方式 | 端点 | 适用 |
|---|---|---|
| 生图端点（默认） | `/v1/images/generations` | dall-e-3、gpt-image-2、grok-imagine-* 等纯生图模型 |
| 对话端点 | `/v1/chat/completions` | Gemini / Nano Banana 系列等多模态模型 |

对话端点走 `service.complete()`，再从回复正文里把图片捞出来，依次尝试：
data URI → Markdown 图片链接 → 裸图片链接。`size` 对这类模型无效（Gemini 用 aspectRatio），
需要特定比例就写进提示词。

**不改开关也能自愈**：线路仍设为「生图端点」时，只要中转明确回「该模型不在
`/v1/images/generations` 上」，插件会自动改走对话端点重试一次，不用人工干预。
普通报错（500、429 等）不会触发这个回退，免得白烧一次额度。
面板试跑的故障日志里会标出每条线路**实际用的端点**。

### ⚠️ 两条已知限制

中央模块的 `complete()` 只把 `message.content` 当文本交回来，所以：

1. **中转把图片放在 `message.images[]` 时插件拿不到** —— content 为空还会撞上
   中央模块的「接口返回了空消息」。插件会把这个错误翻译成明确提示，告诉你这种中转
   需要改 `modules/ai_llm` 才能支持。
2. **无法传 `modalities: ["image","text"]`** —— `complete()` 没有透传额外参数的口子。
   多数中转靠模型名就能触发出图，但要求必带该参数的中转在插件侧无解。

判断办法：面板「试跑生图」跑一次，故障日志会原样显示中转的真实回复或报错，
一眼就能看出属于哪种情况。

## 处理流程

1. 场景开关、描述长度上限与本地违规词
2. 频率检查：每人冷却、每会话冷却、每人每日、全局每日。
   **被限流的请求只回一句提示，不写运行日志** —— 它没有真正发起画图
3. AI 内容审核：独立一次模型请求，只接受「安全」或「内容违规，已禁止发送」
4. 提示词优化：中央对话模型把中文描述改写成生图提示词，失败回落原文
5. 拼接固定前后缀并截断
6. 按线路顺序出图：生图端点走 `generate_image()`，对话端点走 `complete()`，失败自动切下一条
7. 上传图床 → 发 Markdown → 写入历史；**生成成功却没送达时换下一条线路重来**

并发闸只套在第 6 步的生图上；审核与提示词优化不占额度。

## Web 面板

侧边栏「AI 画图」，七页：

| 页面 | 内容 |
|---|---|
| 概览 | 指标、场景开关、回复文案、发送方式与图床状态 |
| 生图线路 | 尺寸、投递失败重试次数；每条线路可选生图端点或对话端点（Gemini），可排序、启停、失败切换 |
| 提示词 | 改写开关、接口与模型、系统提示、固定前后缀，以及试跑生图 |
| 限流 | 描述最大字数、冷却、每日配额、并发、主人豁免，以及历史保留策略 |
| 安全 | AI 审核开关与 Prompt、审核不可用时的策略、本地违规词 |
| 历史记录 | 出图画廊，可搜索、分页、单条删除、清空；标题挂出图总数与本地图片占用空间 |
| 运行日志 | 请求表格：状态（成功/失败/拦截）、用户、场景、线路、耗时、失败原因 |

接口挂在 `/api/ext/ai-draw/*`，复用框架后台登录认证。

### 试跑生图

只在面板里预览，**不上传图床、不发到聊天**——省掉一次图床额度。
图片优先读本地留存（`/image?id=N`）；关掉「保存图片到本地」时改为内联 data URI 返回，
预览不依赖任何存储设置。这类记录在运行日志里标为「面板试跑」，与真实投递区分。

试跑**逐条线路单独跑**（不让中央模块把失败合并成一句话），页面上给出完整的故障转移日志：

```
#1 失败   OpenAI 中转 / dall-e-3   1.2 s   HTTP 500: upstream provider exploded, request-id=abc123
#2 成功   备用中转 / sd3           8.4 s   成功
```

每条线路的**原始报错原样保留**（不截断成 500 字），带耗时和顺序，全部线路失败时也一样列出。
这些日志只回给页面、**不入库**，历史里仍旧只留一条汇总记录。

某条线路只给了服务器下载不到的 URL 时，试跑仍会用它出预览，但标注
「聊天里这条线路会被判定失败」—— 免得面板看着正常、群里却发不出去。

## 限流

框架 `@handler(cooldown=...)` 只是存进 handler 字典、`core/` 里没人读它，所以自己实现：

| 项 | 默认 | 取值 |
|---|---|---|
| 画面描述最大字数 | 1000 | 10 ~ 4000 |
| 每人冷却 | 30 秒 | 0 = 关闭 |
| 每会话冷却 | 5 秒 | 0 = 关闭 |
| 每人每日 | 20 张 | 0 = 不限 |
| 全局每日 | 200 张 | 0 = 不限 |
| 最大并发 | 2 | 最小 1 |

超长与被限流的请求一样，只回一句提示、**不写运行日志**，也不吃每日额度。
超长文案支持 `{limit}` 占位符。

每日配额只数**成功**的记录，失败与拦截不吃额度。冷却在内存里，
每日配额从 SQLite 现算，热重载不会清零。

## 数据

`data/`（已 gitignore）：

- `config.json` —— 插件配置，不含 API Key
- `history.db` —— SQLite 历史记录，默认留 500 条
- `images/` —— 本地留存的出图，默认留 200 张，滚动清理

接口返回 URL 时，留存前会校验目标是公网地址，拒绝回环、内网、链路本地与云元数据地址。
历史与图片超上限时，旧记录连同图片文件一起删除。
